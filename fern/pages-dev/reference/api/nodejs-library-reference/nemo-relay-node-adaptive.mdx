## Functions

### `defaultConfig`

Creates a default adaptive config.

The config has `version` 1 and no sections. Add state, telemetry, and scheduler sections to it.

**Returns**

An adaptive config with no sections.

**Remarks**

The config does nothing until it is wrapped with `ComponentSpec` and activated.

```ts
export declare function defaultConfig(): Config;
```

### `inMemoryBackend`

Creates a backend spec that keeps adaptive state in process memory.

The state is private to the process and is lost when it exits.

**Returns**

A backend spec with kind `in_memory`.

**Remarks**

Use `redisBackend` when several processes must share state.

```ts
export declare function inMemoryBackend(): BackendSpec;
```

### `redisBackend`

Creates a backend spec that keeps adaptive state in Redis.

Processes that use the same Redis instance and key prefix share the state.

**Parameters**

- `url`: Redis connection URL.
- `keyPrefix`: Prefix for every key the backend writes.

**Returns**

A backend spec with kind `redis`.

**Remarks**

`keyPrefix` defaults to `nemo_relay:`.

```ts
export declare function redisBackend(url: string, keyPrefix?: string): BackendSpec;
```

### `responseCacheConfig`

Creates response-cache settings.

Fields in `config` replace the defaults; fields left out keep them. The result is one section of an adaptive config, not a plugin kind.

**Parameters**

- `config`: Response-cache settings to set.

**Returns**

Complete response-cache settings.

**Remarks**

The defaults are an in-memory backend, a `bypassRate` of 0, no caching of nondeterministic requests, and an empty `namespace`. Validation rejects the empty `namespace`, so set it before validating.

```ts
export declare function responseCacheConfig(config?: ResponseCacheConfig): ResponseCacheConfig;
```
