Choose configuration for the way you use Relay. Start with `plugins.toml` for
exporters, guardrails, and other plugin behavior. The CLI also uses `config.toml`
for gateway, coding-agent, and provider settings.

## Configure Plugins

Start with [Use Plugins](/configure-plugins/about) to choose existing components for
observability, adaptive tuning, PII redaction, or resource metrics.
Edit their settings in `plugins.toml`, or use the CLI editor:

```bash
nemo-relay plugins edit
```

Refer to [Plugin Configuration](/configure-plugins/plugin-configuration-files)
for file locations, precedence, and validation. Use
[Manage Plugins](/configure-plugins/discoverable-plugins) to install additional
plugins.

## Configure Coding Agents and Gateways

Edit CLI gateway, agent, and provider settings with:

```bash
nemo-relay config edit
```

Persistent coding-agent integrations read user and system configuration.
Copy the settings you need from a quick-start project into those files before
switching to persistent use. Follow
[Prepare Relay Configuration](/nemo-relay-cli/plugin-installation#prepare-relay-configuration)
for the handoff, [CLI Configuration](/nemo-relay-cli/configuration) for file
selection, and [Provider Authentication](/nemo-relay-cli/authentication) for
credentials.

For an organization-managed deployment, use
[Configuration and Managed Clients](/daemon/configuration).

## Configure Observability

The built-in `observability` plugin exports Agent Trajectory Observability
Format (ATOF) events, Agent Trajectory Interchange Format (ATIF) trajectories,
and OpenTelemetry data. Choose an exporter in
[Observability](/configure-plugins/observability/about), then follow
[Observability Configuration](/configure-plugins/observability/configuration).

OpenTelemetry supports three configuration paths:

- **Configured network export:** Set an explicit endpoint and choose a `full`,
  `gen_ai`, or `openinference` trace projection. Use `header_env` or `header_file`
  to reference credentials for that endpoint.
- **Automatic network export:** Standard `OTEL_EXPORTER_OTLP_*` endpoint
  environment variables activate the matching trace, log, and metric pipelines.
  An explicit `opentelemetry.enabled = false` disables automatic export;
  `OTEL_SDK_DISABLED=true` disables Relay's OTLP exporters.
- **Local trace files:** Write OTLP data to a file sink without a network endpoint.

Refer to [OpenTelemetry](/configure-plugins/observability/opentelemetry) for
environment-variable behavior and
[Trace File Sinks](/configure-plugins/observability/opentelemetry#trace-file-sinks)
for local output.

## Configure Application and Framework Integrations

Use [Initialize Plugins](/configure-plugins/initialize-plugins) to activate
configured plugins through the Python, Node.js, or Rust SDK. Follow your
[framework integration guide](/supported-integrations/about) or
[application instrumentation guide](/instrument-applications/about) for the
runtime lifecycle.

For adaptive behavior, use [Adaptive Configuration](/configure-plugins/adaptive/configuration).
For process-wide stderr and file logging, use
[Operational Logging](/reference/operational-logging).
