## Release 0.10

NeMo Relay 0.10 is under development. This page will track its user-visible
changes, compatibility updates, and fixed known issues.

### LLM Execution Codec Context

Relay now passes the selected request and unary-response codec context to every
LLM execution interceptor. Policies can use Relay's host-owned codec to inspect
or safely rewrite the final provider request and decode a completed unary
response without importing or copying Relay's codec implementations. Streaming
interceptors receive request codec access only.

**Breaking change:** Callback signatures change across Rust, Python, Node.js,
Go, C, native plugins, and Rust and Python gRPC workers. Python
language-binding streaming and public C callbacks also gain the logical LLM
name. Native plugins must rebuild for the internal ABI v7 layout, and affected workers
must regenerate their protobuf bindings and rebuild. Authored compatibility
labels remain `native_api = "1"` and `grpc-v1`; plugin manifests must use a
Relay range that begins at 0.10 or otherwise excludes 0.9. Refer to the
[Migration Guides](/reference/migration-guides) for callback shapes and upgrade
steps.

### Fixes and Other Changes

- Scope-stack forks, managed LLM and tool execution callbacks, and
  late-registered subscribers now preserve the exact OpenTelemetry parent
  context, keeping managed LLM `traceparent` headers aligned with exported
  spans.
- `PropagationContext.to_traceparent()` now returns an imported W3C
  `traceparent` unchanged, including its original trace and span IDs.
- OpenTelemetry spans whose parent was not observed by an exporter now join
  the outer trace instead of starting a separate trace.
- Rootless propagation from a local Relay scope still starts a separate
  OpenTelemetry trace. Rootless capture retains a previously imported W3C
  parent, so remove its W3C fields to force a new trace in that case.
- Explicit-root capture continues to use the supplied root for the receiver's
  trace unless the sender imported a W3C parent, which retains precedence.
- Scopes and managed calls with a popped parent reuse the current stack's
  trace instead of deriving a new trace ID from the scope or managed call.
- Invalid Relay identifiers no longer prevent later valid OpenTelemetry events
  from exporting.

## Known Issues in 0.10

An off-stack parent handle does not retain its historical W3C context. If it
belongs to a different trace than the current stack, managed-call headers can
differ from an exporter's retained parent context. Capture and import the
parent's propagation context before leaving that trace instead of reusing only
the handle.

## Release 0.9.1

NeMo Relay 0.9.1 improves OpenTelemetry coverage and managed Codex routing,
and fixes response-cache behavior for Anthropic compaction.

### Highlights

- The `gen_ai` OpenTelemetry projection adds authoritative request, response,
  usage, reasoning, embedding, and tool attributes. Managed streaming requests
  now report time to first chunk through the trace attribute
  `gen_ai.response.time_to_first_chunk` and the matching metric histogram.
  Relay also records the version of a wrapped Claude Code or Codex executable
  in matching observability metadata.
- OpenTelemetry log and metric endpoints can now promote selected root-scope
  metadata into their resource attributes with
  `promote_resource_metadata_prefixes`. Derived log and metric endpoints
  inherit the trace endpoint setting. Use only controlled, low-cardinality
  metadata values; Relay falls back to the configured base resource when its
  fixed resource-lineage or resource-pipeline limits are reached.
- GenAI tool spans now include the resolved conversation ID and preserve every
  non-null sanitized JSON tool argument and successful result.
- Managed Codex deployments now route ChatGPT OAuth requests to the native
  ChatGPT Codex backend when no administrator OpenAI credential is configured.
  When an administrator credential is configured, Relay replaces the inbound
  OAuth credential before forwarding to that upstream.

### Compatibility and Migration

<Warning title="Upgrade Action Required for Daemon Operators">

The primary `nemo-relay daemon` process now reads TOML logging settings only
from `[daemon.logging]`. It no longer falls back to `[logging]`.

</Warning>

Move logging settings for the primary daemon service to `[daemon.logging]`.
Other Relay processes continue to use `[logging]`; CLI and environment logging
overrides retain their existing precedence. For the required configuration and
Rust struct-literal updates, and telemetry attribute rename, refer to the
[Migration Guides](/reference/migration-guides).

### Fixes and Other Changes

- Anthropic Messages requests that use server-side compaction, continue from a
  compaction block, or send a compaction beta header now bypass the response
  cache. The live provider response preserves compaction lifecycle and streaming
  behavior; the bypass mark reports `anthropic_compaction`.
- Codex permission requests without a tool-call ID are accepted when exactly
  one active tool in the same session matches the request's name and arguments.
- OpenTelemetry logs and traces now use the same observed-event root when a
  scope's local parent was not exported. Relay also avoids adding a unique
  session UUID metric dimension so equivalent measurements can aggregate.
- Python development dependency constraints now require patched releases of
  `anyio` and `soupsieve`.

## Known Issues in 0.9.1

Response-cache replay does not support Anthropic server-side compaction. Relay
therefore sends affected requests to the live provider instead of caching them.
For affected request shapes, refer to
[Response Cache](/configure-plugins/adaptive/response-cache#llm-eligibility-and-limits).
