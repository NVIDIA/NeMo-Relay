[NVIDIA NeMo Relay](https://docs.nvidia.com/nemo/relay) helps you observe and
control what happens inside agent runs without rewriting the agent stack you
already have. It gives coding agents, applications, framework integrations,
middleware, and observability backends a shared runtime for scopes, policy,
plugins, and lifecycle events. Relay records canonical lifecycle events in Agent
Trajectory Observability Format (ATOF) that subscribers and exporters consume.

For more information about the benefits and features, refer to
[Tracing Agent Harness Behavior with NVIDIA NeMo Relay](https://developer.nvidia.com/blog/tracing-agent-harness-behavior-with-nvidia-nemo-relay/).

<Note>
Relay does not replace your agent framework, model provider, application logic,
observability backend, or guardrail authoring system. It connects those systems
through shared scopes, middleware, plugins, and lifecycle events. For how Relay
complements OpenTelemetry GenAI conventions and other observability or evaluation
products, refer to
[How NeMo Relay Relates to Other Tooling](/about-nemo-relay/ecosystem#how-nemo-relay-relates-to-other-tooling).
</Note>

## Core Concepts
{/* @tpl:formatting
List up to six core concepts using noun phrasing and title casing. Include this
section only for concepts readers should understand before diving deeper.
*/}

Explore the core concepts to understand how NeMo Relay models agent runs. Rust is
the source of truth for runtime behavior; the Python and Node.js bindings expose
the same core model, while Go and the raw C FFI are experimental and source-first.

<CardGroup cols={2}>

<Card title="Scopes" href="/about-nemo-relay/concepts/scopes">

Give runs, turns, tools, LLM calls, and subagents clear parent-child relationships, automatic cleanup, and request isolation.
</Card>

<Card title="Events" href="/about-nemo-relay/concepts/events">

Record canonical lifecycle activity, including marks for point-in-time events such as session starts, compaction, or skill loads.
</Card>

<Card title="Subscribers" href="/about-nemo-relay/concepts/subscribers">

Consume the same event stream to produce ATOF events, ATIF trajectories, and typed OpenTelemetry output.
</Card>

<Card title="Middleware" href="/about-nemo-relay/concepts/middleware">

Block, sanitize, transform, route, retry, or replace execution around managed LLM and tool calls.
</Card>

<Card title="Plugins" href="/about-nemo-relay/concepts/plugins">

Turn on reusable observability, guardrail, adaptive, and exporter behavior from configuration.
</Card>

<Card title="Provider Codecs" href="/about-nemo-relay/concepts/codecs">

Keep provider-native request and response semantics consistent when Relay intercepts routed traffic.
</Card>

</CardGroup>
