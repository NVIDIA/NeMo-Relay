## Goal

Run one Hermes Agent turn and write its session, model, and tool lifecycle to a
local Agent Trajectory Observability Format (ATOF) file.

Use a Hermes Agent installation with native NeMo Relay integration on a platform
with a supported Relay native wheel. Do not install the former Hermes Agent Relay
observability plugin or launch Hermes Agent through the `nemo-relay` CLI.

This quick start configures local Relay event export. Hermes Agent shared-metrics
collection and transmission to Nous have separate consent controls.

Use the event relationships to follow model and tool work through a run and
check where the expected activity occurred.

## Prerequisites

Before you start, make sure you have:

- Linux, Apple Silicon macOS, or Windows Subsystem for Linux 2 (WSL2)
- Hermes Agent with native Relay support, plugin diagnostics in `hermes doctor`, and `chat --oneshot`
- A configured Hermes Agent model with inference access: a provider API key or a supported authenticated session
- `jq` 1.6 or newer for the JSON event check; check your version with `jq --version`
- Permission to install Hermes Agent in your user environment

<Steps toc={true}>

## Install

Install Hermes Agent on Linux, macOS, or WSL2:

{/* quickstart-block {"id":"install","role":"manual","cwd":".","shells":["bash"],"session":"main","reason":"Interactive Hermes Agent installation and provider authentication; pre-provision the declared host for unattended tests"} */}
```bash
curl -fsSL https://hermes-agent.nousresearch.com/install.sh | bash
```

Complete the setup prompts and confirm that `hermes` can use your model
provider before continuing. Check that `hermes chat --help` lists `--oneshot`;
older builds can lack support for this recipe.

If Hermes Agent does not yet have a working provider and model, select the NVIDIA
provider in `hermes model`, supply an
[NVIDIA API key](https://build.nvidia.com/settings/api-keys), and choose an
available [build.nvidia.com model](https://build.nvidia.com/explore/discover).

<Note icon="circle-info">
Relay does not choose the model. If Hermes Agent already has a working provider and
model, keep that configuration. Hermes Agent manages its supported Relay dependency
version.
</Note>

## Configure

Create a disposable working directory and make sure the agent can write files there:

{/* quickstart-block {"id":"workspace","role":"run","cwd":".","shells":["bash"],"session":"main","timeout_seconds":180} */}
```bash
mkdir relay-hermes-quickstart
cd relay-hermes-quickstart
```

Save the following files and run the remaining commands from this directory.

Save the following configuration as `plugins.toml` in the directory where you
will start Hermes Agent:

{/* quickstart-block {"id":"plugins","role":"file","cwd":"relay-hermes-quickstart","path":"plugins.toml"} */}
<Code src="_code/plugins.toml" language="toml" title="plugins.toml" />

Select that file in the shell that will start Hermes Agent:

{/* quickstart-block {"id":"environment","role":"run","cwd":"relay-hermes-quickstart","shells":["bash"],"session":"main","timeout_seconds":180} */}
```bash
export HERMES_NEMO_RELAY_PLUGINS_TOML="$PWD/plugins.toml"
```

Run the diagnostic in that same shell:

{/* quickstart-block {"id":"doctor","role":"manual","cwd":"relay-hermes-quickstart","shells":["bash"],"session":"main","reason":"Hermes Agent doctor checks unrelated optional services and can exit nonzero despite a valid Relay configuration; inspect its Relay section"} */}
```bash
hermes doctor
```

In the **NeMo Relay Plugins** section, confirm that the selected file is listed,
plugins are enabled, and no Relay configuration problems are reported. If the
section is missing, update Hermes Agent before continuing. Resolve problems in
**NeMo Relay Plugins** and your selected inference provider.

<Note icon="circle-info">
`hermes doctor` checks configuration without loading plugin code. It also checks
optional services unrelated to Relay and can exit nonzero when they are
unconfigured; those warnings do not require enabling the services for this quick
start.
</Note>

<Note icon="circle-info">
Hermes Agent does not discover repository-local configuration automatically. The
explicit path replaces the user configuration file; system configuration still
applies. Relay plugins affect every profile hosted in the same Hermes Agent process.
Use separate processes when profiles require different plugin policies.
</Note>

<Warning>
ATOF output can contain sensitive prompts, responses, tool arguments, and tool
results. Working-directory paths can reveal usernames and repository names.
Protect `logs/events.jsonl` even when full payload export is disabled.
</Warning>

## Run

From the same directory, run a one-shot turn with the common validation prompt:

{/* quickstart-block {"id":"run","role":"run","cwd":"relay-hermes-quickstart","shells":["bash"],"session":"main","timeout_seconds":180} */}
```bash
rm -f -- relay-check.txt logs/events.jsonl &&
hermes chat --oneshot -q "Use a file-writing tool to create relay-check.txt in the current working directory containing exactly RELAY_QUICKSTART_TOOL_OK. Then reply with RELAY_QUICKSTART_RESPONSE_OK."
```

<Note icon="circle-info">
Hermes Agent closes the Relay session before this command exits, allowing queued
observability records to finish writing.
</Note>

## Verify

The tool marker proves that the agent created the requested file. The event
marker proves that Relay recorded matching start/end records for the required
turn or agent, tool, and model work. The response marker is the agent's reply;
it is checked separately from the captured lifecycle.

The verification command prints `RELAY_QUICKSTART_TOOL_OK` and `RELAY_QUICKSTART_EVENTS_OK`.

<details>
<summary>Run the verification checks</summary>

Run these checks after Hermes Agent exits:

{/* quickstart-block {"id":"verify","role":"run","cwd":"relay-hermes-quickstart","shells":["bash"],"session":"main","timeout_seconds":180} */}
```bash
jq -eRs 'gsub("^\\s+|\\s+$"; "") == "RELAY_QUICKSTART_TOOL_OK"' relay-check.txt > /dev/null &&
jq -se '
  . as $events |
  def closed($category):
    any($events[]; . as $end_event |
      .kind == "scope" and .scope_category == "end" and
      .category == $category and
      any($events[]; .kind == "scope" and .scope_category == "start" and
        .uuid == $end_event.uuid and .name == $end_event.name and
        .category == $end_event.category and .parent_uuid == $end_event.parent_uuid));
  length > 0 and
  all(.[]; .atof_version == "0.1" and (.kind == "scope" or .kind == "mark")) and
  closed("agent") and closed("tool") and closed("llm")
' logs/events.jsonl > /dev/null &&
printf 'RELAY_QUICKSTART_TOOL_OK\nRELAY_QUICKSTART_EVENTS_OK\n'
```

The verification command prints the following output when its checks pass:

{/* quickstart-block {"id":"expected","role":"expected","cwd":"relay-hermes-quickstart","from":"verify","match":"exact-lines"} */}
```text
RELAY_QUICKSTART_TOOL_OK
RELAY_QUICKSTART_EVENTS_OK
```

</details>

The agent's final reply should include `RELAY_QUICKSTART_RESPONSE_OK`; its
surrounding wording can vary.

<Note icon="circle-info">
These markers confirm the tool-created file and matching start/end records for
agent, tool, and LLM work.
</Note>

### Inspect the Recorded Activity

Read the completed model calls from the same event file:

<Tabs>
<Tab title="Unix shell">
{/* quickstart-block {"id":"inspect","role":"run","cwd":"relay-hermes-quickstart","shells":["bash"],"session":"main","timeout_seconds":180} */}
```bash
jq 'select(.kind == "scope" and .scope_category == "end" and .category == "llm") |
  {name, category, category_profile, uuid, parent_uuid, timestamp, metadata}' logs/events.jsonl
```
</Tab>
</Tabs>

`category` and `name` identify the recorded work. The same `uuid` pairs its
start and end records; `parent_uuid` connects it to its enclosing scope.
`timestamp` records when this event occurred. For model calls, `category_profile`
and `metadata` can include the model identity and completion status, depending
on the integration. These fields let you follow a call through the run without
requiring full prompt or response capture.

</Steps>
