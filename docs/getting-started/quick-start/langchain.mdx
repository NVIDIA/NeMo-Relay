## Goal

Run one LangChain agent and write its model and tool lifecycle to a local Agent Trajectory Observability Format (ATOF) file.

Use the event relationships to follow model and tool work through a run and
check where the expected activity occurred.

## Prerequisites

Before you start, make sure you have:

- Python 3.11 or newer
- `uv`
- Inference access: an [NVIDIA API key](https://build.nvidia.com/settings/api-keys) for this example, or credentials for your own provider

<Steps toc={true}>

## Install

Create a project and install the NeMo Relay version for these docs with the
LangChain and NVIDIA model provider extras.
For an existing `uv` project, run only the `uv add` command from its directory.

{/* quickstart-block {"id":"install","role":"run","cwd":".","shells":["bash","powershell"],"session":"main","timeout_seconds":600} */}
```bash
mkdir relay-langchain-quickstart
cd relay-langchain-quickstart
uv init
uv add "nemo-relay[langchain,langchain-nvidia]==0.11.0"
```

Set your NVIDIA API key for the current shell:

{/* quickstart-block {"id":"credentials","role":"input","cwd":"relay-langchain-quickstart","shells":["bash"],"session":"main","env":"NVIDIA_API_KEY"} */}

```bash
export NVIDIA_API_KEY="your-api-key"
```
</Tab>

<Tab title="Windows PowerShell">

<Note icon="circle-info">
Relay does not impose a model choice. This copyable example selects the public
[`nvidia/nemotron-3.5-lightning-30b-a3b`](https://build.nvidia.com/nvidia/nemotron-3.5-lightning-30b-a3b)
model through the NVIDIA provider. To use another model or provider, replace
the example's `model` argument and configure that provider's credentials.
The NVIDIA provider reads `NVIDIA_API_KEY`. In the LangChain string, the first `nvidia:`
selects the provider; the remaining `nvidia/...` value is the model ID.
</Note>

## Run

The example creates a LangChain agent with one marker tool. The
`require_marker_tool` middleware makes this test request a tool result before
its final answer; it is test scaffolding rather than required Relay setup.
`NemoRelayMiddleware` observes model and tool execution, and
`NemoRelayCallbackHandler` records the framework lifecycle. Plugin activation
loads `plugins.toml`, the outer scope groups the request, and flushing finishes
writing queued events before verification.

In your own agent, keep the Relay middleware, callback, activation, scope, and
flush lifecycle. Replace the marker tool and prompt with your application work;
the assertions after invocation and event-file checks belong to this example.

## Verify

The program checks the tool result, final assistant response, and paired ATOF
agent, tool, and LLM records. A successful run prints these markers in order:

{/* quickstart-block {"id":"expected","role":"expected","cwd":"relay-langchain-quickstart","from":"run","match":"exact-lines"} */}
```text
RELAY_QUICKSTART_TOOL_OK
RELAY_QUICKSTART_RESPONSE_OK
RELAY_QUICKSTART_EVENTS_OK
```

<Note icon="circle-info">
The model can use different wording around the response marker. These checks
validate a live provider call; they do not make the model deterministic.
</Note>

### Inspect the Recorded Activity

Print one completed model call from the event file:

{/* quickstart-block {"id":"inspect","role":"run","cwd":"relay-langchain-quickstart","shells":["bash","powershell"],"session":"main","timeout_seconds":180} */}
```bash
uv run python -c "
import json
from pathlib import Path
events = [json.loads(line) for line in Path('logs/events.jsonl').read_text().splitlines()]
call = next(event for event in events if event.get('scope_category') == 'end' and event.get('category') == 'llm')
fields = ('name', 'category', 'category_profile', 'uuid', 'parent_uuid', 'timestamp', 'metadata')
print(json.dumps({key: call.get(key) for key in fields}, indent=2))
"
```

`category` and `name` identify the recorded work. The same `uuid` pairs its
start and end records; `parent_uuid` connects it to its enclosing scope.
`timestamp` records when this event occurred. For model calls, `category_profile`
and `metadata` can include the model identity and completion status, depending
on the integration. These fields let you follow a call through the run without
requiring full prompt or response capture.
