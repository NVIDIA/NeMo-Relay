Memory inspection explains how the diagnostic service uses its admitted
storage. It reports reserved backing, occupancy, and retained-entry footprints;
the optional resource context describes a separately sampled process or system.
It does not attribute application heap allocations to a plugin or turn diagnostic
reservation into an RSS measurement.

All read surfaces reuse the [query and authorization contract](/reference/diagnostics-api).
Component identities can contain restricted metadata even when the memory view
omits event text. Keep memory pages within the same inspection boundary as snapshots.

## Aggregate Backing and Occupancy

`Diagnostics::memory_usage()` and `DiagnosticsReader::memory_usage()` return the
same `DiagnosticMemoryUsage` view. The history and detail-pool fields distinguish
reserved backing, occupied capacity, and logical text:

| Fields | Meaning |
| --- | --- |
| `event_slot_bytes`, `event_capacity` | Compiled size of one private retained event header and the admitted number of history slots. |
| `history_reserved_bytes` | Complete circular-buffer allocation, including shared header, alignment, and all event slots. |
| `history_occupied_bytes` | Retained event count multiplied by `event_slot_bytes`; excludes the shared buffer header and unused slots. |
| `detail_capacity_bytes`, `detail_metadata_bytes`, `detail_reserved_bytes` | Whole-block payload capacity, metadata reserved for every block, and their combined backing bytes. |
| `detail_bytes` | Existing gauge for occupied payload blocks, including unused space within those blocks. |
| `detail_logical_bytes`, `detail_slack_bytes` | Retained UTF-8 message/correlation bytes and unused payload space within occupied blocks. |

`detail_reserved_bytes` equals `detail_capacity_bytes + detail_metadata_bytes`.
`detail_bytes` equals `detail_logical_bytes + detail_slack_bytes`. Free payload
capacity is `detail_capacity_bytes - detail_bytes`. Block metadata differs from
the existing `metadata_bytes` gauge, which describes admitted registration text.
A pool rounds payload capacity down to whole blocks; block size comes from
`DiagnosticLimits.detail_block_bytes` and defaults to 256 bytes.

Each retained event packs its message, session ID, and request ID into one
block chain. Compact ranges preserve the three fields, including present but
empty strings; UTF-8 characters are never split across blocks. Fields are
admitted in message, session, then request order. A field that cannot fit in the
whole pool is omitted without evicting prior evidence; selected fields can
reclaim older events when free blocks are exhausted. Projection callbacks receive
only `DiagnosticOutputSummary`; retained detail and caller correlation stay in
the explicitly inspected snapshot.

Inspection derives the breakdown from existing storage. Logical text bytes
require a bounded scan of block metadata when the view is requested; recording
adds no size ledger, per-event size field, or additional retained store. Disabled
contexts report zero for every gauge. Eviction reduces occupancy and returns
blocks for reuse while the reserved backing remains allocated. These values do
not measure resident pages or whole-process working-set memory.

Memory inspection is separate from the canonical diagnostic snapshot. Embedded
bindings expose aggregate gauges through reader metadata. The memory view adds bounded
per-entry/component pages and independently sampled resource context through
[`inspect_memory` and the authorized memory route](/reference/diagnostics-memory#detailed-memory-inspection).
Canonical aggregate JSON quantities use lossless decimal strings; the native
Rust aggregate fields retain `usize`.

## Detailed Memory Inspection

`DiagnosticsReader::inspect_memory(&DiagnosticQuery)` returns a bounded
`MemoryInspectionLease`. The query uses the same selectors and caps as snapshots;
`max_events` limits entry rows. Memory pages have their own schema version (1) and
cursor discriminator. A snapshot cursor cannot resume a memory page. Each page
rechecks the retained-state revision and authorization; reads never freeze history.

| Surface | Memory operation |
| --- | --- |
| Rust | `reader.inspect_memory(&query)`; `as_bytes()`, borrowed `components()`/`entries()`, explicit owned `to_memory_page()` |
| CLI | `nemo-relay diagnostics --memory`; add `--daemon-url` to inspect broker backing |
| Authorized HTTP | `GET /_nemo_relay/v1/diagnostics/memory?query=ENCODED_JSON` |
| Python | `reader.inspect_memory(query)` or `reader.inspect_memory_json(query)` |
| Node.js | `reader.inspectMemory(query)` or `reader.inspectMemoryJson(query)` |
| Experimental Go | `reader.InspectMemory(query)` or `reader.InspectMemoryJSON(query)` |
| Experimental C | `nemo_relay_diagnostics_memory_json`; release output with `nemo_relay_string_free` |

The shared HTTP route applies to gateways, daemon brokers, and managed Relay
workers under their existing whole-context authority. The daemon's periodic
worker cache continues to retain ordinary diagnostic pages; `--worker --memory`
is not supported. The new memory view does not expand plugin-worker read grants,
introduce remote memory caching, or cause a broker to poll worker resources.

## Interpret Memory Accounting

Every response contains whole-context `aggregate` values and a reconciliation:

```text
aggregate.reserved_bytes = component_occupied_bytes
                        + shared_or_unassigned_reserved_bytes
```

Component charges include the actual compiled registration element, every assigned
code-counter and window element (even unused ones), extension descriptors, and
retained entry footprints. The shared residual includes free capacity, history
headers/padding, service structures, and query/projection workspaces. It is not a
measure of unused memory. Replacement registrations never inherit prior charges;
refresh updates the existing registration without creating an archive.

Each entry includes its owning registration and acceptance sequence, with:

```text
occupied_bytes = header_bytes + detail_payload_bytes + detail_metadata_bytes
logical_text_bytes + detail_slack_bytes = detail_payload_bytes
```

Message and correlation fields share one packed chain. A three-byte message with
no correlation occupies one 256-byte payload block under the default profile:
three logical bytes and 253 slack bytes, plus one block's metadata and its fixed
event header. Empty/absent text needs no payload blocks. Compiled layouts vary by
target; no address, pool index, message, or correlation text is returned.

`selection` totals cover all matching rows, while `page` totals cover this response
only. Event filters do not redefine whole-component charges. Entry bytes overlap
component bytes; occupied bytes overlap reservation. Do not add these quantities.
The shared `loss` contract reports history eviction, omission, rejection, and
sequence saturation independently of page truncation. The aggregate and attribution
share one diagnostic capture revision; transient query/projection occupancy is
sampled during that capture.

## Bounded Cost and Rust Views

Memory and snapshot reads share `max_queries`, row/text budgets, and the encoded
`max_snapshot_bytes` ceiling. Each admitted query workspace adds a numeric array
indexed by `max_components`, capped component/entry rows, and fixed capture
metadata. Startup includes these allocations in `max_owned_bytes`; profiles sized
exactly to the previous implementation may need a larger ceiling. Zero-query
contexts allocate no query scratch. Recording adds no size ledger or resource read.

The accounting scan visits admitted components, counters, windows/extension
reservations, retained events, and live detail blocks. It does not scan all events
once per component. It holds diagnostic state only while copying bounded data;
serialization, resource access, language conversion, and network delivery occur
after that lock is released. Byte-cap sizing can visit copied rows repeatedly.

Focused allocation checks after a warm-up read found no steady-state capture
allocations. First-use runtime helpers can allocate outside the retained backing.
Both memory and ordinary snapshot leases offer allocation-free borrowed row
iterators over copied storage. Their lifetimes are tied to the lease; they do not
pin history. JSON access also borrows admitted output. Owned decoding is explicit
and allocates caller-owned values outside the service budget. Binding conversion
uses the existing independent copy admission and returns caller-owned results.

Compiled element sizes vary with target and build. Use `event_slot_bytes` and
the live accounting fields when sizing a deployment. A configured byte ceiling
is a storage admission bound, not a latency guarantee. Choose polling intervals
that account for the bounded scan and serialization cost under your workload.

## Resource Context and Precision

The resource manager retains one fixed memory-only projection from existing
successful polling/on-demand collections. Inspection reads that projection; it
never initializes the resource plugin, schedules collection, changes its target,
or reads configuration files. The resource plugin's existing resolver owns:

```toml
# Within an existing resource_metrics component's configuration:
[components.config.memory_inspection]
enabled = true
stale_after_millis = 30000
```

The cache uses a finite field vocabulary and eight limit-event slots. Excess
memory coverage or limit events produce `capacity_unavailable`; the previous
valid sample, if any, remains with its actual identity and age. There is no
unbounded map, historical sample list, or retained `Arc` snapshot graph. The fixed
cache is outside diagnostic core reservation; a query's copied resource view is
inside its admitted workspace. `projection_slot_bytes` describes the cache
layout, not the entire manager or collector. Concurrent existing collectors also
have their own collection workspaces. If the copied resource sample prevents even
one diagnostic row (or an empty diagnostic envelope) from fitting the requested
response cap, the response omits that sample with `capacity_unavailable` and retries
the diagnostic page. Resource context cannot force loss of an otherwise fitting
diagnostic response.

A successful memory page reports resource availability separately from
diagnostic state. The `resource` field has explicit `disabled`, `awaiting_target`, `not_yet_sampled`, `available`, `failed`,
`invalidated`, `unsupported`, or `capacity_unavailable` status. A retained sample
has a separate `stale` flag and local monotonic completion age. Absent fields mean
not reported (unsupported or unreadable); they do not become zero. A non-finite
measurement uses `kind: non_finite`.

Sample identity combines collector UUID, runtime generation, target generation,
stream, and a shared ordinal assigned at collection start. An older completion
cannot replace a newer attempt's result; target changes and teardown invalidate
the cache. Collection start/end/duration, diagnostic capture time/revision, and
sample age remain separate. There is no atomic cross-subsystem snapshot.
Resource samples can change between pages even when the diagnostic continuation
is still valid; inspect the identity and age on each page.

Verified process association compares PID and process-start identity captured by
the existing collector. `host_process` includes the embedding application's other
work; `host_process_tree` includes descendants. A supervised child tree may exclude
Relay. Global samples remain system context. Samples can be shared across local
diagnostic sources and must not be summed once per source.

Individual fields retain their own scope: system capacity remains system data in
an application snapshot; environment accounting/limits/pressure remain environment
data. Resident, private, footprint, virtual, and peak resident measurements retain
their platform meaning, units, and reported process coverage. Integral values use
`{kind: "integer", value: "..."}`; finite converted fractions use
`{kind: "decimal", value: 1.25}`. Existing resource API serialization is unchanged.

Canonical aggregate memory quantities use decimal strings. Rust retains
its existing native `usize` aggregate fields with checked wire conversion; Python
uses `int`, Node uses `bigint`, and Go uses `DiagnosticNumber`. Node `info().memory`
uses `bigint` for aggregate memory quantities. Other small schema/PID fields
remain ordinary numbers. Go preserves tagged measurement values as `json.RawMessage`
for exact integer/decimal decoding.

Diagnostic backing is not process working set or per-plugin heap usage. Eviction
reuses backing; it does not promise an RSS reduction. Do not subtract reservation
from RSS or distribute RSS proportionally across components. This view adds no
health classification, pressure action, CPU attribution, or metrics export.

The resource completion path copies measurements into diagnostics; it never sends
inspection identities, queries, retained detail, or joined pages back into resource
marks, logs, sanitizers, or exporters. Future exports require a separately approved
aggregate numeric projection and cardinality/disclosure policy.
