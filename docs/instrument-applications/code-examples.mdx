Each reference file defines `run_example` in Python and Rust or `runExample` in

await asynchronous functions. Keep that application's scope, subscriber, and
cleanup. These functions are integration fragments rather than standalone
programs.

## Invocation API Selection

Prefer Execute APIs whenever you can pass the actual tool or provider function
to Relay. Use manual start/end APIs only when another library owns the invocation
and exposes only lifecycle notifications. Do not retry a failed Execute call
through a manual API.

The following table shows which API to use based on your integration need:

| Need | Preferred API | Use When |
|---|---|---|
| Run a tool with full instrumentation | `tools.execute`, `toolCallExecute`, `tool_call_execute` | Application code owns the callback. |
| Run an LLM call with full instrumentation | `llm.execute`, `llmCallExecute`, `llm_call_execute` | Application code owns the provider call. |
| Run a streaming LLM call | `llm_stream_execute`, `typedLlmStreamExecute`, `llm_stream_call_execute` | You need chunk collection and one final aggregate end event. |
| Emit start/end manually | `call` and `call_end` helpers | A framework owns the real invocation boundary. |
| Emit a checkpoint | `scope.event`, `event` | You need milestone visibility inside an active scope. |
| Emit an OTLP log mark | Generic mark API with typed `severity` | A sanitized checkpoint should become a telemetry log record. |
| Record an OTLP metric | `metric` | One validated measurement group should be routed to the metric pipeline. |
| Attach work to one request | Scope-local registration helpers | Middleware or subscribers should disappear when that scope closes. |

## Streaming LLM Execution

Use the streaming helper when a model returns its response in chunks. The
collector gathers those chunks. The finalizer builds one response from the
collected data for the LLM end event.

When the stream ends normally, Relay runs the finalizer automatically. If you
stop reading early, close the stream to stop the producer and finalize the
partial response. Relay records that early close as an interruption.

The following examples read one chunk and then close the stream. Closing runs
the finalizer and completes the LLM lifecycle with the collected response. These
examples use local generators, so they require no provider credentials.

returned stream yields JSON chunks.

### Handle Stream Failures

Always close a stream after you finish reading it, including after a read
error. Use `await stream.aclose()` in Python, `await stream.close()` in
Node.js, or `stream.close().await` in Rust. Closing waits for producer cleanup
and finalization. Repeated calls return the same close result.

In Node.js, both `llmStreamCallExecute` and `typedLlmStreamExecute` report
failures at the following points:

| Failure | Where It Is Reported |
|---|---|
| The provider callback throws or rejects before returning an async iterable. | The call that creates the stream rejects. |
| The provider returns a value that is not an async iterable. | The call that creates the stream rejects. |
| The iterator or collector throws or rejects while reading a chunk. | `stream.next()` rejects. The stream stops. |
| Producer cleanup fails. | `stream.close()` rejects. |
| The finalizer throws, rejects, or returns a value that cannot be encoded as JSON. | `stream.close()` rejects. |

Node.js collectors and finalizers can return a `Promise`. Relay waits for a
collector before yielding its chunk. It waits for the finalizer before
reporting the end of the stream.

If the finalizer fails, the combined response is `null`. Relay omits the response
payload from the end event. It does not use the call's `data` value as a
fallback. A finalizer failure marks an otherwise completed LLM end event as
`ERROR`.

In Node.js, `stream.close()` gives priority to a stream error that `next()` has
not yet reported. Cleanup errors take priority over finalizer errors. If `next()`
already reported the stream error, close does not report it again. It can
still report a cleanup or finalizer error. Handle errors from both reading
and closing. Keep the read error if cleanup also fails, and report the
cleanup error separately. If a stream error has not yet been reported,
`close()` reports that error and logs any accompanying producer cleanup failure.

### Cancel the Producer

Closing requests cancellation, but the producer must be able to stop its work.
In Node.js, the provider callback receives `(request, signal)`. Pass this
`AbortSignal` to provider operations that support it. Stop pending work when
the signal aborts. Release resources in the iterator's cleanup path.

Close has no cleanup timeout. It can remain pending if the producer does not
stop. An asynchronous collector must also finish after the producer stops.
Set time limits on provider operations and make cleanup finish promptly.

### Wait for Subscriber Delivery

Stream completion and subscriber delivery are separate steps. Reading the
last chunk or closing the stream does not wait for queued response sanitizers
and subscribers. Close the stream first. Then flush subscribers before
reading captured events. Before checking exporter output or shutting down,
also complete the exporter's flush, export, or shutdown operation.
Refer to [Waiting for Delivery](/about-nemo-relay/concepts/subscribers#waiting-for-delivery)
for the flush API and exporter requirements for each binding.

## Middleware Registration Families

The runtime exposes the same registration families for tool and LLM calls:

- Sanitize-request guardrails change emitted start-event payloads only
- Sanitize-response guardrails change emitted end-event payloads only
- Conditional-execution guardrails return an allow-or-block decision
- Request intercepts change the real request before execution
- Execution intercepts wrap the callback and may post-process or short-circuit
- LLM stream execution intercepts wrap streaming provider callbacks

Every family also has a scope-local surface:

- Python: `nemo_relay.scope_local.register_*`
- Node.js: `scopeRegister*`
- Rust: middleware `scope_register_*` functions under
  `nemo_relay::registry`; subscriber scope registration under
  `nemo_relay::subscriber`

Use [Add Middleware](/instrument-applications/advanced-guide) for an end-to-end policy example and [API Reference](/reference/api) for symbol-level details.
