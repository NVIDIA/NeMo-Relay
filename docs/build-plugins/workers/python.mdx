The `examples/python-grpc-worker-plugin` package uses `nemo-relay-plugin` 1.0.0.
It supports all 17 [callback types](/build-plugins/workers/middleware-and-continuations).
Its configuration selects which callbacks to register. The SDK handles generated
protobuf bindings, the authenticated server, and task cancellation.

## Inspect Normalized LLM Content

Worker codec capabilities return normalized dictionaries. Keep those dictionaries
for callbacks and encoding; use `nemo_relay_plugin.codecs` for local, read-only
content inspection:

```python
from nemo_relay_plugin import codecs

annotation = {"messages": [{"role": "user", "content": "hello"}]}
view = codecs.last_message(annotation)
if view is not None:
    assert view.text() == "hello"
    for entry in view.parts():
        print(entry.kind, entry.location.message_index, entry.location.field)
```

These helpers accept normalized annotations from codec decoding, request
intercepts, or event category profiles. They do not decode raw provider payloads.
Use the invocation's `WorkerRequestCodec.decode()` or
`WorkerResponseCodec.decode_response()` capability first when starting with a
raw request or response. Content inspection itself performs no RPC and does not
require the main `nemo_relay` runtime extension.

| Worker helper | Selection |
| --- | --- |
| `last_message(request)` | Exactly the final request item, or `None` for empty history |
| `message(request, index)` | Any history item, including negative Python indices |
| `instructions_view(request)` | Top-level instructions, without a history fallback |
| `output(response)` | Current normalized message and separate tool calls, including textless output |
| `MessageView.from_message(message)` | A standalone normalized message dictionary |
| `MessageView.from_content(content)` | A standalone string or normalized content-part list |

Views expose `parts()`, `text_parts()`, and `text()`. Entries, locations, tool
views, and payload views follow the [Python content snapshot API](/integrate-into-frameworks/provider-codecs#python-content-snapshots).
Tool payloads retain their string, JSON, null, or complete-content representation.
Default text includes text/refusals and supported shallow native fallbacks;
tools, reasoning, media, and arbitrary nested metadata are excluded. Empty text
remains distinct from absent text, and newline joining preserves whitespace.

The module also provides `system_prompt(request)`, `last_user_message(request)`,
and `response_text(response)` with the same selection and extraction rules as
the main Python binding. A selected textless item does not cause a search for
another item with text.

Selection copies only the selected item/content/output into immutable Python
storage. Iterators and entries remain usable after the input dictionary or
parent view is deleted. Later edits to the input do not change a snapshot;
returned media/native and tool payload dictionaries/lists are independent copies.
Retaining entries can retain selected snapshot data. Locations describe the
normalized snapshot, not stable editing handles or provider-wire offsets.

Out-of-range history indices raise `IndexError`. Invalid selected normalized
content raises `ValueError`. The helpers preserve the dictionary-based callback
and wire contracts; they add neither mutable redaction nor live streaming
extraction.

## Internal Diagnostic Observations

Use `await runtime.diagnostics()` to obtain diagnostics for the activation.
The SDK sets up delivery once and reuses the host's selected context. It does
not create a worker-local store or enable diagnostic collection.

This example matches the Rust native and Rust worker example. Register its
component once during setup, then retain it in the callbacks that perform lookups.
Python supports `async def register`, so that hook can await the helper using
`ctx.runtime`. Keep both returned handles for the activation.
It declares separate failure and success codes, records positive occurrence counts,
and attaches a request ID. Call the failure helper only after observing an
unavailable backend. Call the success helper only after a completed lookup.

Handle registration and recording failures separately from execution failures.
Python raises `DiagnosticDeliveryError`, whose `kind` field identifies the error.
The helpers expose those errors so the caller can apply its delivery policy.
Do not propagate an optional diagnostic failure as the lookup's result.

`try_record_lazy` returns `None` after local queue admission. It does not return a
host acceptance receipt. An inactive component returns without recording. Disabled
or unsupported collection skips the observation factory. A full queue also skips
the factory. `diagnostics.availability` reports negotiated availability.

Check `diagnostics.delivery_stats()` for dropped, rejected, and uncertain work.
Use `await diagnostics.flush(timeout)` to wait for earlier queue work.
The timeout is in seconds. Flush does not return per-record receipts or acknowledge
disk storage. Never replay uncertain observations into a new session.

Use `await component.close()` when the component's work ends. SDK shutdown
limits diagnostic drain time and closes delivery tasks. Explicit delivery shutdown
uses `await diagnostics.close(timeout)`. Canonical snapshot and memory reads are
not available to workers, even when a native plugin has a read grant.

Refer to [Plugin Diagnostics](/build-plugins/diagnostics) for the shared pattern,
built-in code declarations, and native/worker API differences. The
[delivery protocol](/build-plugins/workers/grpc-v1-protocol#diagnostic-delivery)
defines host limits, retries, and session authority.

## Test the Package

Run the package tests before creating a managed environment.

From the repository root, enter the example directory and run its tests:

```bash
cd examples/python-grpc-worker-plugin
uv run --locked --group test pytest
```

Every test creates its own worker instance and mock host context, and any one test can
be selected by node ID without running the rest of the suite. The tests separate
configuration, JSON Schema, source digest, wheel packaging, registration metadata,
sanitizers, policies, request outcomes, continuations, streams, and runtime cleanup.
A digest mismatch is a packaging failure, not an activation warning.

## Configure the Snapshot Location

Before starting a worker, Relay copies its package and runtime files into an
activation snapshot. This is a separate directory for that activation. Set
`NEMO_RELAY_PLUGIN_SNAPSHOT_DIR` in the environment that starts Relay to choose
where snapshots are stored. Relay creates the directory if needed. Keep it
outside plugin packages and all copied entrypoint and library directories:

```powershell
$env:NEMO_RELAY_PLUGIN_SNAPSHOT_DIR = "C:\\nrs"
```

```bash
export NEMO_RELAY_PLUGIN_SNAPSHOT_DIR=/var/tmp/nrs
```

```python
from nemo_relay_plugin import ConfigDiagnostic, DiagnosticLevel, Json, PluginContext, WorkerPlugin, serve_plugin

class ExamplePythonWorker(WorkerPlugin):
    plugin_id = "examples.python_grpc_worker"
    allows_multiple_components = False

    def validate(self, config: Json) -> list[ConfigDiagnostic]:
        return validate_config(config)

    def register(self, ctx: PluginContext, config: Json) -> None:
        diagnostics = validate_config(config)
        errors = [
            item for item in diagnostics
            if item.level == DiagnosticLevel.ERROR
        ]
        if errors:
            raise ValueError(errors[0].message)
        settings = normalized_config(config)
        if settings["observe"]["enabled"]:
            self._register_observation(
                ctx, settings["tag"], settings["observe"]
            )
        if settings["requests"]["enabled"]:
            self._register_requests(
                ctx,
                settings["tag"],
                settings["requests"],
                settings["execution"],
            )
        self._register_runtime(ctx, settings["tag"], settings["runtime"])
        if settings["execution"]["enabled"]:
            self._register_execution(ctx, settings["tag"], settings["execution"])

async def main() -> None:
    await serve_plugin(ExamplePythonWorker())
```

Relay calls validation before registration, but `register` still rejects invalid direct
use instead of assuming every possible host followed the expected sequence.

The corresponding manifest tells Relay to install this directory and import `main` from

## Install and Activate the Package

Use the following procedure to install the package into Relay's managed environment and
start the worker:

1. From `examples/python-grpc-worker-plugin`, create a clean temporary Relay state and
   add the manifest.

   ```bash
   relay_tmp="$(mktemp -d)"
   relay_config="$relay_tmp/gateway.toml"
   : > "$relay_config"
   nemo-relay --config "$relay_config" plugins add ./relay-plugin.toml
   ```

   `plugins add` creates an isolated managed environment and installs
   `source.manifest_root` with pip. Set `NEMO_RELAY_PYTHON` only for this add operation
   when Relay must use a non-default base interpreter. Standard pip index, proxy,
   certificate, and wheelhouse variables control dependency resolution.

2. Enable the component and start Relay.

   ```bash
   nemo-relay --config "$relay_config" plugins enable examples.python_grpc_worker
   nemo-relay --config "$relay_config" --bind 127.0.0.1:4040
   ```

   The activation report should identify `examples.python_grpc_worker`, and the worker
   handshake should advertise all 17 supported surfaces.

## Verify Behavior and Clean Up

Use the following procedure to verify each callback family and clean up the managed
environment:

1. Exercise one allowed and one blocked tool, one allowed and one blocked model, a unary
   LLM continuation, and a multi-chunk stream. Confirm configured headers, sanitized
   event fields, preserved annotations, pending marks, and lazy chunk transformation.
2. Cancel a long-running async callback and abandon a worker stream. Confirm the SDK
   task receives cancellation and the worker's `finally` cleanup runs. A synchronous
   callback cannot be preempted, so the example keeps synchronous work bounded.
3. Emit a mark, use a nested scope, create and bind an isolated stack, then force a
   failure. Confirm the prior scope context is restored and the stack is dropped.
4. Stop Relay with `Ctrl+C`, then remove the plugin and delete the temporary state from
   the shell where `relay_tmp` and `relay_config` remain defined.

   ```bash
   nemo-relay --config "$relay_config" plugins remove examples.python_grpc_worker
   rm -rf -- "$relay_tmp"
   ```

`plugins remove` deletes the Relay-managed environment. Copying a Python worker manifest
into `plugins.toml` is not an equivalent installation path because no attested environment
would exist. Check that Relay creates and later removes the managed environment. Each feature
group must produce the expected result. Cancellation must run cleanup, and no
worker process should remain after shutdown.
