The `examples/rust-grpc-worker-plugin` project is the Rust version of the
[Python worker](/build-plugins/workers/python). It uses `nemo-relay-worker` 1.0.0
and implements `Plugin`. It supports all 17
[callback types](/build-plugins/workers/middleware-and-continuations). Its
configuration selects which callbacks to register. The SDK starts the authenticated
`nvidia.nemo.relay.worker.v1` server from Relay's activation environment.

## Internal Diagnostic Observations

Use `runtime.diagnostics().await` to obtain diagnostics for the activation.
The SDK sets up delivery once and reuses the host's selected context. It does
not create a worker-local store or enable diagnostic collection.

This example matches the Rust native and Python worker example. Register its
component once from asynchronous code, then retain it for later lookups.
`Plugin::register` returns a future and can initialize helpers during registration.
This example captures shared state in an asynchronous callback and initializes the
helper once with a Tokio `OnceCell`.
Cache initialization failure as well to avoid repeated registration attempts.
It declares separate failure and success codes, records positive occurrence counts,
and attaches a request ID. Call the failure helper only after observing an
unavailable backend. Call the success helper only after a completed lookup.

<Code src="_code/internal_diagnostics.rs" language="rust" title="Lookup diagnostics" lines="4-69" showLineNumbers={false} />

Handle registration and recording failures separately from execution failures.
Rust returns `DiagnosticDeliveryError` variants.
The helpers expose those errors so the caller can apply its delivery policy.
Do not propagate an optional diagnostic failure as the lookup's result.

`try_record_lazy` returns `Ok(())` after local queue admission. It does not return a
host acceptance receipt. An inactive component returns without recording. Disabled
or unsupported collection skips the observation factory. A full queue also skips
the factory. `diagnostics.availability()` reports negotiated availability.

Check `diagnostics.delivery_stats()` for dropped, rejected, and uncertain work.
Use `diagnostics.flush(Duration).await` to wait for earlier queue work.
The timeout is a `std::time::Duration`. Flush does not return per-record receipts
or acknowledge disk storage. Never replay uncertain observations into a new session.

Use `component.close().await` when the component's work ends. SDK shutdown
limits diagnostic drain time and closes delivery tasks. Explicit delivery shutdown
uses `diagnostics.close(Duration).await`. Canonical snapshot and memory reads are
not available to workers, even when a native plugin has a read grant.

Refer to [Plugin Diagnostics](/build-plugins/diagnostics) for the shared pattern,
built-in code declarations, and native/worker API differences. The
[delivery protocol](/build-plugins/workers/grpc-v1-protocol#diagnostic-delivery)
defines host limits, retries, and session authority.

## Configure the Snapshot Location

Before starting a worker, Relay copies its package and runtime files into an
activation snapshot. This is a separate directory for that activation. Set
`NEMO_RELAY_PLUGIN_SNAPSHOT_DIR` in the environment that starts Relay to choose
where snapshots are stored. Relay creates the directory if needed. Keep it
outside plugin packages and all copied entrypoint and library directories:

```powershell
$env:NEMO_RELAY_PLUGIN_SNAPSHOT_DIR = "C:\\nrs"
```

```bash
export NEMO_RELAY_PLUGIN_SNAPSHOT_DIR=/var/tmp/nrs
```

## Build and Calculate Integrity

Building a Rust worker requires `protoc` 31.1 or later and Buf 1.75.0 or later.
Install both on `PATH`, or select them with `PROTOC` and `BUF`. The first build
needs access to the Buf Schema Registry to download the locked validation schema.

Build the executable and create a manifest for your platform:

1. Build and test the example from its own directory.

   ```bash
   cargo nextest run
   cargo build --target-dir target
   ```

2. Copy `relay-plugin.toml` to `relay-plugin.local.toml` and replace
   `<platform-worker-file>` with `nemo-relay-rust-grpc-worker-plugin-example` on macOS or
   Linux, or the same name with `.exe` on Windows.

3. Calculate the SHA-256 digest before registration. On macOS run:

   ```bash
   shasum -a 256 target/debug/<platform-worker-file>
   ```

   On Linux run `sha256sum target/debug/<platform-worker-file>`. In PowerShell run
   `Get-FileHash -Algorithm SHA256 target/debug/<platform-worker-file>`. Put the lowercase
   hexadecimal value after `sha256:` in `[integrity].sha256`.

Success at this stage means tests pass, the manifest entrypoint resolves to the built
executable, and integrity describes the exact executable that starts.

## Register and Start the Worker

Use the following procedure to register the manifest and inspect worker activation:

1. From the repository root, validate, add, and enable the local manifest.

   ```bash
   nemo-relay plugins validate ./examples/rust-grpc-worker-plugin/relay-plugin.local.toml
   nemo-relay plugins add --user ./examples/rust-grpc-worker-plugin/relay-plugin.local.toml
   nemo-relay plugins enable examples.rust_grpc_worker
   ```

2. Start Relay from the repository root. Inspect the activation report
   and confirm the handshake reports plugin identity, SDK and runtime metadata,
   `nvidia.nemo.relay.worker.v1`, multiple-component behavior, and all 17 surfaces.

   ```bash
   nemo-relay --bind 127.0.0.1:4040
   ```

`Plugin::register` is an asynchronous registration step. It parses the validated JSON
and registers callbacks through `PluginContext`. Those callbacks return futures.

```rust
pub struct DocumentationWorker;

impl Plugin for DocumentationWorker {
    fn plugin_kind(&self) -> &str {
        "examples.rust_grpc_worker"
    }
    fn allows_multiple_components(&self) -> bool {
        false
    }
    fn validate(&self, config: &serde_json::Map<String, Json>) -> Vec<ConfigDiagnostic> {
        let config = &Json::Object(config.clone());
        config::validate(config)
    }

    fn register<'a>(
        &'a self,
        config: &'a serde_json::Map<String, Json>,
        context: &'a mut PluginContext,
    ) -> nemo_relay_worker::PluginFuture<'a, ()> {
        Box::pin(async move {
            let config = &Json::Object(config.clone());

            let settings = ExampleConfig::parse(config).map_err(WorkerSdkError::InvalidInput)?;
            if settings.observe.enabled {
                register_observation(context, &settings);
            }
            if settings.requests.enabled {
                register_requests(context, &settings);
            }
            register_execution(context, &settings);
            Ok(())
        })
    }
}
```

The binary contains no transport configuration. `serve_plugin` reads the activation
environment, starts the authenticated SDK service, and stays alive until Relay sends the
shutdown stage.

```rust
use nemo_relay_rust_grpc_worker_plugin_example::DocumentationWorker;
use nemo_relay_worker::{Result, serve_plugin};

#[tokio::main]
async fn main() -> Result<()> {
    serve_plugin(DocumentationWorker).await
}
```

## Exercise and Remove the Worker

Use the following procedure to verify the registered callbacks and stop the worker
cleanly:

1. Exercise allowed and blocked calls, unary and streaming continuations, codec decode and
   encode proxies, pending marks, optimization contributions, nested and isolated scopes,
   and cancellation.
2. Disable and remove the component only after in-flight invocations have settled.

   ```bash
   nemo-relay plugins disable examples.rust_grpc_worker
   nemo-relay plugins remove examples.rust_grpc_worker
   ```

Success means shutdown rejects new invocations, cancels or drains active work, closes the
authenticated endpoint, stops the process, and leaves no owned runtime registrations.
